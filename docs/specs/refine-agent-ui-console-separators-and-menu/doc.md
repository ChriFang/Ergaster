# 对齐 agent-ui 的会话区分隔、思考模式提示与右键菜单尺寸

## 背景与目标
在上一轮视觉迁移后，`desktop-tools` 已经完成了黑色主题收敛、Sidebar 图标化、消息头像图标化、思考块视觉增强等工作，但与 `agent-ui` 对比后，右侧会话区仍有几处可以继续收紧并简化：

- 标题面板、会话面板、输入面板仍保留较明显的独立卡片感，占用垂直空间。
- 思考模式开关下方仍有一行解释文案，占用额外高度。
- 会话区右键菜单尺寸仍偏大，与当前整体紧凑风格不完全协调。

本轮目标是在不改变现有会话逻辑、输入逻辑、右键菜单行为和消息模型的前提下，继续向 `agent-ui` 的极简分隔方式靠拢，让右侧控制台区域更省空间、更统一。

## 对比结论

### 1. 会话区三段结构的分隔方式
`agent-ui` 的右侧区域采用“单线分层 + 轻容器”的处理方式：
- 标题区主要依靠底部一根分隔线。
- 会话滚动区不再用厚重的外层卡片包裹。
- 输入区主要通过顶部一根分隔线与会话区分开，真正的输入容器保持轻量。

当前 `desktop-tools` 右侧区域虽然已比之前更紧凑，但标题区、会话区、输入区仍都有较完整的边框/背景/圆角容器，仍存在视觉厚度和空间浪费。

### 2. 思考模式提示文案
`agent-ui` 的输入区不保留常驻说明文案，只保留“思考模式”开关本身，通过控件状态表达语义。

当前 `desktop-tools` 的这行提示文案：
- `开启后模型会先进行推理，再输出最终答案。`

会增加一行高度，不利于保持输入区紧凑。

### 3. 右键菜单尺寸
`agent-ui` 的菜单风格更小、更薄：
- 菜单容器更窄。
- 圆角更小。
- 外层 padding 更小。
- 菜单项高度更低。
- 字号更克制。

当前 `desktop-tools` 的上下文菜单相比之下仍略显厚重。

## 技术方案

### 1. 把右侧控制台三段从“多卡片”收敛为“单线分隔”
在不重构 DOM 的前提下，以 CSS 为主完成收敛：
- `ConsolePanel` 保持当前三段结构：标题区、会话区、输入区。
- 标题区改为更轻的容器，弱化完整卡片边框感，重点保留底部分隔线。
- 会话滚动区去掉厚重外框，减少外层边框和大圆角，让网格背景区更自然铺开。
- 输入区将分隔职责更多交给顶部细线，而不是依赖整块厚重外层卡片。

这样可以在不改业务结构的前提下，达到更接近 `agent-ui` 的空间利用率。

### 2. 去掉思考模式下方说明文案
在 `Composer` 中移除说明文字节点，只保留：
- 思考模式开关
- 取消 / 发送按钮

同时配套收紧 `composer-meta` 的布局，避免删除文案后残留不必要空白。

### 3. 收紧右键菜单尺寸
保持 `MessageContextMenu` 结构不变，仅在样式层收紧：
- 减小菜单容器最小宽度。
- 减小菜单圆角。
- 减小菜单容器 padding。
- 减小菜单项 padding。
- 适当下调字号与行高。

这样既保留现有“复制 / 重置会话”逻辑，也让菜单与当前整体紧凑黑色科技风保持一致。

## 数据流与行为要求
- 不修改消息发送逻辑。
- 不修改思考模式开关行为。
- 不修改消息复制逻辑。
- 不修改空白区右键“重置会话”逻辑。
- 不修改消息选中文本右键“复制”逻辑。

本轮只收敛展示层与分隔方式，不改任何功能语义。

## 边界条件与兼容要求
- 标题区简化后，默认模式与已选智能体两种头部结构都必须保持可读。
- 会话区外框减弱后，网格背景不能影响消息正文阅读。
- 输入区说明文案删除后，思考模式开关仍需具备足够辨识度。
- 右键菜单缩小后，点击热区仍需足够稳定，不应因为过小而影响可用性。
- 所有调整需兼容当前桌面窗口缩放和窄宽度布局。

## 风险与处理
- 如果会话区外框弱化过度，右侧区域层次可能变得不清晰，因此需用细线分隔和背景深浅差来补足。
- 如果右键菜单缩得过小，会影响可点性，因此应控制在“更紧凑但仍可稳定点击”的范围内。
- 删除说明文案后，若思考模式语义不够明确，可优先通过按钮视觉状态补强，而不是重新加解释文本。

## 预期结果
完成本轮后，应达到以下结果：
- 右侧标题区、会话区、输入区更接近 `agent-ui` 的单线分隔风格。
- 整体纵向空间更节约，右侧控制台更紧凑。
- 思考模式开关下方说明文案被移除。
- 会话区右键菜单更小、更薄、更符合当前整体风格。
- 不引入任何功能回归。

## 建议执行顺序
建议先从样式层收紧分隔结构与右键菜单尺寸，再删除输入区说明文案，最后执行类型检查与构建验证。
