# 输入记录复用去重修复总结

## 完成内容
已修复“从左侧输入记录选择后直接发送会产生两条相同记录”的问题，并保留“选择后编辑再发送可作为新输入保存”的行为。

## 具体改动

### 持久化层去重与置顶
修改 `src/main/input-history-service.ts`：
- 将追加输入记录逻辑从“简单头插”改为“去重后置顶”
- 现在写入历史文件时会先移除已有同内容记录，再把当前记录放到顶部
- 仍然保留最多 100 条记录

核心变化：
- 从：`[entry, ...current]`
- 改为：`[entry, ...current.filter((item) => item !== entry)]`

这样即使历史文件中已经存在重复项，再次发送相同内容后也会自动收敛为一条。

### 前端历史回填与发送逻辑
修改 `src/renderer/App.tsx`：
- 新增 `selectedHistoryDraft`，用于追踪当前输入是否来源于历史回填
- 点击左侧历史记录时，同时设置：
  - `input`
  - `selectedHistoryDraft`
- 新增 `handleInputChange`：
  - 如果用户对回填文本进行了编辑，则清空 `selectedHistoryDraft`
- 发送时本地 `inputHistory` 更新逻辑改为“去重后置顶”
- 发送后清空 `selectedHistoryDraft`

## 修复结果
现在行为如下：
- 直接点击历史记录后发送：
  - 不会新增第二条相同记录
  - 该记录会保持唯一并移动到顶部
- 点击历史记录后编辑再发送：
  - 修改后的内容会按新输入正常保存
- 如果历史文件中原先已经有多条相同记录：
  - 再次发送同内容后会自动收敛为一条
