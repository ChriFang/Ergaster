# 将 agent-ui 的视觉设计分步迁移到 desktop-tools

## 背景与目标
当前 `desktop-tools` 的功能结构已经较完整，但从运行效果上看，参考项目 `agent-ui` 在以下方面具备更统一、更现代的视觉表现：

- 左侧品牌栏、导航 tab、设置入口具备更强的图标语义与视觉层级。
- 整体布局更紧凑，字号更小，分割关系更克制。
- 会话区拥有统一的深色主题、科技感网格背景和更清晰的消息层级。
- 用户消息、助手消息、思考过程消息的视觉区分更强。

本次工作目标不是直接照搬 `agent-ui` 的 React 结构，而是在保持 `desktop-tools` 现有业务逻辑、状态流、Electron 架构、消息模型不变的前提下，分批把 `agent-ui` 的核心视觉语言迁移到本项目中，逐步实现更一致的 UI 效果。

## 总体原则
- 只迁移视觉设计，不改动业务行为。
- 优先修改样式和展示层，不重写会话流、智能体管理、输入历史、工具调用链。
- 能直接复用的视觉元素直接迁移；与本项目数据结构耦合的部分，仅迁移外观，不照搬组件实现。
- 按小批次推进，每批都可以独立验证，避免一次性大改造成回归。

## 当前项目与 agent-ui 的主要差异

### 1. Sidebar 品牌栏与导航层级
`agent-ui` 的 sidebar 使用图标化品牌和导航：
- 品牌栏使用 `Hexagon` 图标并带背景块。
- 智能体 tab 使用 `Bot` 图标。
- 输入记录使用 `History` 图标。
- 底部设置入口也使用独立图标与边界分隔。

当前 `desktop-tools` 的左栏已有对应功能，但主要以文字表达为主，图标和层级感偏弱。

### 2. 全局布局与主题语言
`agent-ui` 的整体视觉更紧凑，特征包括：
- 更小的字体与更统一的字重层次。
- 更克制的圆角、padding、间距。
- 更纯粹的黑色系背景。
- 仅依赖细线边框做区块分隔。
- 会话区带科技感网格背景。

当前 `desktop-tools` 已是暗色主题，但偏蓝黑渐变和毛玻璃风格，面板间距、字号、卡片厚度都更大。

### 3. 消息区层级与头像语义
`agent-ui` 的消息区域主要差异：
- 用户消息与助手消息的气泡样式差异更明显。
- 用户头像是人物图标，助手头像是芯片图标。
- 思考过程消息有独立弱强调块，并带小脑图标。
- 整体消息宽度、边框、留白更克制。

当前 `desktop-tools` 虽已区分不同消息类型，但头像仍以字母/文字徽记为主，思考消息和工具消息的视觉层级还可以进一步向 `agent-ui` 靠拢。

## 技术方案

### 方案概述
以“视觉 token 先行、结构节点后改、消息样式最后精修”的方式分批迁移：

1. 先统一全局主题变量、字体、背景、分割线与间距。
2. 再改 sidebar 的品牌栏、tab、底部设置入口视觉。
3. 再改会话区消息头像、气泡、思考块、输入区。
4. 保持所有现有交互逻辑、上下文菜单、重置会话、消息复制、工具确认逻辑不变。

### 字体策略
优先沿用 `agent-ui` 的字体体系思路，即：
- 正文字体采用更紧凑的 sans 字体。
- 技术信息、状态或 metadata 采用 mono 字体。

但由于 `desktop-tools` 不是 Next.js/Tailwind 项目，不能直接复用其字体接入方式，需要在当前 renderer 样式体系中引入等价字体方案并落到 `styles.css`。

### 颜色与主题策略
将当前偏蓝黑玻璃态主题，逐步收敛为更纯粹的黑色背景 + 青蓝强调色体系：
- 主背景更接近纯黑或深灰黑。
- 分区卡片层级减少。
- 多个板块之间优先使用单线分隔。
- 减少高透明度和大面积模糊效果。

### 网格背景策略
在会话主滚动区引入类似 `agent-ui` 的科技感网格背景：
- 通过 `styles.css` 中的双线性渐变实现。
- 仅应用于会话主区域，不影响 sidebar 和输入区可读性。
- 强度需低于消息层，以避免干扰正文阅读。

### 消息视觉策略
在不改变消息数据模型的前提下，进行展示层迁移：
- 用户消息：采用更明确的右侧气泡风格和人物图标。
- 助手消息：采用更明确的左侧气泡风格和芯片图标。
- 思考消息：引入小脑图标、弱色背景、可折叠或类折叠块风格。
- 工具消息：尽量向 `agent-ui` 的技术卡片风格靠拢，但保留本项目的独立消息模型。

## 分批改造建议

### 第一批：全局主题与布局收紧
目标：先把“整体气质”拉近 `agent-ui`。

包括：
- 收紧全局字号、间距、边框、圆角。
- 引入更黑的主背景。
- 调整分割线风格。
- 为会话区增加网格背景。
- 统一标题、描述、辅助信息的字号层级。

预期收益：不改结构即可显著改善整体观感。

### 第二批：Sidebar 图标化与品牌栏改造
目标：迁移左栏最显眼的视觉语言。

包括：
- 品牌栏引入类似 `Hexagon` 的系统图标与背景块。
- 智能体 tab 增加 `Bot` 图标。
- 输入记录 tab 增加 `History` 图标。
- 设置入口增加图标并统一底部边界。
- 收紧左栏间距和项目样式。

预期收益：最直接建立与 `agent-ui` 一致的品牌和导航印象。

### 第三批：消息气泡与头像升级
目标：让聊天区达到更接近 `agent-ui` 的视觉辨识度。

包括：
- 用户头像替换为人物图标。
- 助手头像替换为芯片图标。
- 收紧消息容器宽度、padding、边框。
- 加强用户/助手气泡风格区分。

预期收益：聊天内容本身的质感会明显提升。

### 第四批：思考过程与工具消息样式对齐
目标：补齐 `agent-ui` 中最具特色的“思考过程”视觉语言。

包括：
- 思考消息增加脑图标。
- 引入更弱强调的边框、背景和标题行。
- 视现有实现决定是否保留当前展开方式或演化为更接近 `agent-ui` 的折叠交互。
- 工具消息风格适度技术卡片化。

预期收益：提升高级能力展示效果，同时保持信息层次清晰。

### 第五批：输入区和控制台头部细节微调
目标：做收尾一致性处理。

包括：
- 输入区边框、按钮、开关样式向 `agent-ui` 靠拢。
- 控制台头部收紧信息密度。
- 统一 hover、active、focus 反馈。

预期收益：完成从“风格接近”到“整体一致”的最后一段迁移。

## 边界条件与兼容要求
- 不修改 Electron main/preload 通信逻辑。
- 不修改智能体列表、输入历史、会话重置、消息发送、消息复制、工具确认的行为语义。
- 不将 `agent-ui` 的 Tailwind/Next.js 结构直接复制到本项目。
- 不强行照搬 `agent-ui` 的消息数据结构，尤其是 tool call 与 thinking 数据模型。
- 所有视觉变更都应兼容现有空状态、无智能体状态、运行中状态、错误状态和确认卡片状态。

## 风险与处理
- 若一次性同时改字体、间距、结构，容易造成局部布局挤压或溢出，因此必须分批推进。
- 若引入图标库，需要确认打包体积和 renderer 构建兼容性。
- 黑色主题收得过深可能降低分区辨识度，因此需通过边框、弱背景层和文字对比度补足。
- 网格背景过强会干扰正文阅读，因此应控制透明度。

## 预期结果
完成这轮迁移后，应达到以下结果：
- 左侧品牌栏、tab 与设置入口的图标化视觉与 `agent-ui` 更接近。
- 整体布局更紧凑、字体更统一、主题更偏纯黑且更简洁。
- 会话区具备更明显的科技感网格背景。
- 用户消息、助手消息、思考消息具备更强的视觉区分。
- 在保持 `desktop-tools` 现有功能逻辑不变的前提下，整体 UI 风格尽量贴近 `agent-ui`。

## 建议执行顺序
建议先执行“第一批：全局主题与布局收紧”以及“第二批：Sidebar 图标化与品牌栏改造”，因为这两部分收益最大、风险最低，也最符合你当前提出的具体观察项。
