# Ergaster 项目架构与脉络

## 1. 项目定位与命名

`Ergaster` 是一个基于 Electron 的桌面 AI Agent 工作台：把大模型的推理能力，与本地 Windows 上
真实的操作能力（文件、命令行、Office 文档、邮件、网络请求、剪贴板、托盘）接在一起，让模型能
**多轮思考 + 动手执行**，并由用户在风险动作前把关。

名字取自希腊语 *ἐργαστήρ*（工匠、作坊）——「办事的工作间」。2026 版将原项目名 `Desktop Agent`
统一更名为 `Ergaster`，包名、数据目录、窗口标题、托盘、打包产物名一并更改。

它不是通用聊天壳，而是一个「面向本机操作与工具编排」的智能体客户端。

核心入口与依据：
- `package.json`（`name: ergaster` / `productName: Ergaster`）
- `src/main/index.ts`（窗口、IPC、生命周期）
- `src/main/agent/agent-service.ts`（Agent 主链路）
- `src/main/tools/tool-registry.ts`（工具注册与执行中枢）
- `src/renderer/App.tsx`（页面级状态与装配）

## 2. 技术栈

### 2.1 桌面与运行时
- `Electron 41`，`contextIsolation: true` / `nodeIntegration: false` / `sandbox: false`（preload 需要 Node 能力）
- `preload + contextBridge`，渲染层唯一入口是 `window.desktopApp`

### 2.2 前端
- `React 19` + `TypeScript` + `Vite 6`
- `react-markdown` + `remark-gfm` 渲染消息
- 无 Redux/Zustand：状态由 `App.tsx` + `src/renderer/lib/hooks/*` 的领域 hooks 承担

### 2.3 主进程能力与协议
- Chat Completions 协议（默认 DeepSeek 端点，可配 `apiBaseUrl`，支持 one-api 兼容模式）
- `@modelcontextprotocol/sdk`（MCP 客户端）
- `zod`（工具参数校验）、`yaml`（Skill frontmatter）
- 文档族：`docx`、`exceljs`、`pdfkit`、`mammoth`、`pdf-parse`、`jszip`、`imapflow`、`mailparser`

### 2.4 构建与测试
- `esbuild`：构建 `main` / `preload`（bundle、cjs）
- `Vite`：构建 `renderer`
- `electron-packager` + 自定义 `scripts/package-electron.mjs`：打包分发
- `node:test` + `assert`：单元测试经 esbuild 打包后直接运行

## 4. 进程模型与安全边界

四层结构：

1. **桌面壳层**：创建窗口、托盘、单实例锁、外链拦截、生命周期
2. **Agent 运行时层**：会话消息、模型调用、流式输出、工具轮次调度与取消
3. **能力层**：系统工具 / 用户 Skills / MCP Tools / 能力模块（邮件等）/ 代码工程 / 工作流
4. **UI 层**：会话视图、输入区、各类管理面板、审批弹层、交互式组件卡片

边界设计（见 `src/main/index.ts`）：
- `nodeIntegration: false` + `contextIsolation: true`，Node 能力留在主进程
- `removeMenu()`，自定义标题栏（`titleBarStyle: 'hidden'` + 白色 `titleBarOverlay`）
- `setWindowOpenHandler` 与 `will-navigate` 只放行 http/https 且交给系统浏览器
- `session.setPermissionRequestHandler` 一律拒绝（CVE-2026-70612 的缓解手段）
- 渲染进程崩溃（`render-process-gone`）与渲染层未捕获异常都落 `main.log`，便于定位整窗空白

工程上的好处很直接：**主进程负责「能力」，渲染进程负责「体验」**，敏感操作只有一个入口。

## 5. 启动链路

`src/main/index.ts`：
1. `app.requestSingleInstanceLock()`：已存在实例时唤起主窗口而不是双开
2. `initTrayService()` 注入主窗口句柄（避免循环依赖）
3. `nativeTheme.themeSource = 'dark'`（让原生 select、滚动条按深色渲染）
4. `app.whenReady()` 后：注册确认 / Skill / Agent / MCP / 会话 / 附件 / 邮件 / 工作流 / 代码工程 /
   定时任务 / UI 窗口等 IPC handler
5. `initializeCapabilities()` 初始化能力模块（按模块隔离失败，不阻断其余）
6. 加载本地 Skills、扫描 Agent Profiles
7. 创建主窗口，绑定 Agent / Workflow 流事件并转发给渲染层

渲染层 `src/renderer/main.tsx` 挂载 `App.tsx`，`use-app-bootstrap` 负责首屏初始化：
拉应用信息、配置、当前会话消息、输入历史，重载 Agents，订阅审批请求与流式事件。

## 6. 一次 Agent 请求的主链路

核心在 `src/main/agent/agent-service.ts` + `src/main/tools/tool-registry.ts`。

1. **发起**：渲染层 `window.desktopApp.runAgent()` → 主进程校验（是否有执行中的请求、prompt 是否为空）
   → 加载配置 → 按所选智能体/代码工程组装工具集 → 组装会话消息（Agent 的 `AGENT.md` 作为 system 注入）
2. **调用模型**：`src/main/agent/deepseek-client.ts` 的 `createChatCompletionStream()`，`stream: true`；
   `thinkingModeEnabled` 与按模型区分的推理强度（`reasoning-params.ts`）映射进请求体；
   空闲超时用 `modelIdleTimeoutSeconds` 控制（长回复本身不受限）
3. **流式回传**：`agentService.onStream()` → `webContents.send('agent:stream', payload)` →
   前端把 reasoning 与 content 两类 delta 分别拼到当前 assistant 消息
4. **工具循环**：模型返回 `tool_calls` → 遍历 → `tool-registry` 的 `executeToolCall()` →
   结果以 `tool` 角色消息回注 → 进入下一轮，直到模型不再请求工具或达到 `maxToolRounds`
   （默认 256，上限 1024）
5. **收尾**：会话消息落盘、生成/更新会话标题、写主日志与审计日志

取消与重置：`cancel()` 中断当前请求并清空挂起审批；`reset(scope)` 清空指定作用域的会话上下文。
消息按作用域（默认模式 / 各 agentId / 代码工程）分别维护，互不串味。

## 7. 能力体系

### 7.1 工具注册中心（中枢）
`src/main/tools/tool-registry.ts` 统一管理五类能力：
1. **系统工具**：代码内置注册
2. **用户 Skills**：从 `~/.ergaster/skills` 扫描
3. **MCP Tools**：从已启用的 MCP Server 动态拉取
4. **能力模块工具**：`capabilities/` 登记的模块（如邮件）贡献的工具
5. **配套工具**：`memory_*`、定时任务、代码工程、`ui_form`/`render_ui`、子智能体

职责：定义工具 schema（zod）→ 计算风险等级 → 决定是否需要确认 → 执行 → 记录主日志/审计日志 →
把结果包装成模型可继续消费的 `tool` 消息（并抽取结果里的 base64 图片转成消息图片）。

### 7.2 内置系统工具（按能力分组）
- 本地操作：`open_application`、`open_path`、`get_system_info`
- 文件读取与检索：`read_file`、`list_dir`、`glob_files`、`grep_files`、`count_matches`、`search_files`、`preview_*`
- 文件产出：`create_text_draft`、`create_docx_draft`、`create_pdf_draft`、`create_excel_draft`、
  `create_image_draft`、`list_draft_files`、`move_draft_file`、`update_excel_cells`、`read_excel`
- 格式解析：`extract_word_text`、`extract_ppt_text`、`extract_pdf_text`
- 系统命令：`run_command`、`run_powershell_template`（模板白名单）
- 网络：`http_request`、`download_file`、`extract_archive`
- 扩展：`install_skill`

### 7.3 风险分级与审批
每个工具带 `low / medium / high`。执行前统一走 `requestToolConfirmation()`。
在统一入口之上叠了三层「免打扰」规则（`auto-execute.ts`、`command-allowlist.ts`、`download-engine.ts`）：
- 全局「允许自动执行的工具」清单（仅非 high）
- 命令白/黑名单（黑名单命中强制弹窗且不提供「总是允许」）
- `download_file` 的域名白名单

无人值守链路（定时任务、工作流）只走白名单内动作，超出即拒绝，不会悬挂等待用户。

### 7.4 Skills
目录：`~/.ergaster/skills/<skill>/SKILL.md`（YAML frontmatter + Markdown body）。
两种运行方式：**内容型**（整篇内容注入给模型，支持 `/skill` 指令显式指定）与**工具型**
（`metadata.execute.tool` 映射到已有系统工具）。支持从 GitHub 安装（`skill-installer.ts`，
逐跳复检域名白名单与 SSRF）。

### 7.5 Agents
目录：`~/.ergaster/agents/<id>/{AGENT.md,agent.json}`。一个 Agent = system prompt 正文 + 元数据 +
MCP 绑定（`mcp.enabledServerNames`）。运行时把它注入 system 消息，并据此决定可用的 MCP 工具集。
这是「同一个应用里切换不同角色与工具边界」的机制。

### 7.6 MCP
配置：`~/.ergaster/mcp.json`（`mcpServers` + `defaultAgent.enabledServerNames`）。
以 `StdioClientTransport` 连接外部 Server，`listTools()` 后映射为内部 `ToolDefinition`。
定位是「外部工具能力扩展层」：不必把工具写死在仓库里，且可按 Agent 隔离边界。

### 7.7 能力模块（Capability Module）
`src/main/capabilities/` 是内部功能域的登记点：新增一个域（当前已有 `mail`）只要在这里登记，
初始化与工具组合自动纳入，不必再到 `index.ts` / `tool-registry` 各改一段。
模块自带 `isEnabled(config)`，关闭后其工具不进入模型上下文（省 token）。

### 7.8 代码工程
`~/.ergaster/code-projects/` 记录纳入的本地仓库及其「可写」开关与 MCP 绑定。
`code/` 提供带作用域校验的 `code_read_file` / `code_write_file` / `code_edit_file` / `code_grep` /
`code_glob` / `code_list_dir`：写入前做 diff 与备份，落盘用「同目录临时文件 + rename」保证原子性，
编辑副本存于 `~/.ergaster/code-edits/<conversationId>/`。

### 7.9 工作流
`workflow/` 提供三类运行：内置「辩论」（多角色立论/批判/裁决）、「深度研究」（规划/收集/抽取/
核验/缺口/成稿）、自定义工作流（可视化节点编排，定义存 `~/.ergaster/workflows/<id>/workflow.json`）。
运行态通过 `workflow:*` 流事件回传；报告可导出 Markdown。

### 7.10 其他
- **邮件**：IMAP 只读（账户、邮箱、检索、读信、已读标记），密码经 `safeStorage` 加密后存
  `~/.ergaster/mail-accounts.json`
- **长期记忆**：`~/.ergaster/memory/memory.json`，注入 + 节流自动抽取，另有独立 `memory-audit.log`
- **定时任务**：`~/.ergaster/scheduled-tasks/`，进程内调度器按调度规格触发 Agent 任务
- **交互式 UI**：模型可产出沙箱 HTML 卡片或结构化表单，大表单可开独立窗口（`ui-window-manager`
  用一次性 token 认领窗口，提交后回注给 Agent）

## 8. 会话与消息持久化

- 会话存在 `~/.ergaster/conversations/<conversationId>/`，消息分段存储 + 懒加载分页
  （`conversation-service.ts` 负责读写与分页，`conversation-truncate.ts` 负责截断）
- 附件随会话存 `conversations/<id>/attachments/`，元数据在 `attachments-meta.json`；
  粘贴图片先进 `os.tmpdir()/ergaster-paste`，发送后复制进会话目录
- 进程内仍保留一份按作用域索引的消息缓存供运行时拼上下文
- 渲染层另有 localStorage 级轻量状态：输入历史（`ergaster:input-history:*`）、上次激活会话
  （`ergaster.last-active-session`）、`/` 指令最近使用（`ergaster:slash-recent`）

## 9. 配置、日志与调试开关

- **配置**：`userData/config.json`，由 `core/config-service.ts` 读写，`shared/config.ts` 做
  `sanitizeConfig()` 归一化与 `toMaskedConfig()` 脱敏回显（密钥永不下发原文）
- **日志**（`core/audit-log.ts`，按 5MB 轮转）：
  - `log/main.log` 运行日志
  - `log/audit.log` 结构化审计（Agent/Tool 的时间、工具名、风险、状态、摘要）
  - `log/dump-req.log` 请求原始 dump（需调试开关）
  - `log/memory-audit.log` 记忆写入审计
- **调试开关**：`userData/test.ini`，`core/debug-config.ts` 按 mtime+size 缓存解析

## 10. 前端结构

- `App.tsx`：页面级状态控制器与布局装配（模式切换、面板开关、事件订阅接线）
- `lib/hooks/`：领域状态拆出——`use-app-bootstrap`、`use-chat-session`、`use-settings-state`、
  `use-workflow-session`、`use-composer-state`、`use-conversation-drafts`、`use-context-menu`
- `features/`：
  - `layout/`：`SidebarPanel`、`ConsolePanel`、`ChatConsoleView`、`SettingsDialogShell`
  - `messages/`：消息列表、Markdown 渲染、工具调用卡片、UI 表单/HTML 卡片、文件预览
  - `composer/`：输入区、附件、`@` 路径引用、`/` 指令菜单、历史调起
  - 管理面板：`settings/`、`skills/`、`agents/`、`mcp/`、`workflows/`、`activity/`
  - `confirmation/`：工具审批弹层；`ui-window/`：独立交互窗渲染
- 样式集中 `src/renderer/styles.css`（CSS 变量 + 自研组件，无 UI 库）；无 i18n，中文内联

## 12. 开发、构建、测试、打包

- `npm run dev`：`concurrently` 并行跑 Vite（renderer）、esbuild watch（main）、esbuild watch
  （preload）、`electronmon`（等端口与产物就绪后启动 Electron）
- `npm run build`：清 `dist` → 构建 renderer / main / preload
- `npm run typecheck`：两套 tsconfig 分别检查渲染层与 node 侧
- `npm test`：单个 esbuild 命令把全部 `*.test.ts` 打成一个 bundle 后运行
- `npm run dist:win32` / `dist:win64` / `dist:mac` / `dist:mac-arm` / `dist:mac-universal`：
  产物落 `release/`（应用名、可执行文件名取自 `productName`）

## 13. 已知局限

1. **`App.tsx` 仍是装配中心**：状态已拆到 hooks，但组件树与面板开关仍集中在一处，继续加功能会变长
2. **MCP 治理偏粗**：仅 stdio，工具风险统一 `low`，别名是运行时生成的 `mcp_0_1` 之类，可读性一般
3. **日志脱敏未真正启用**：`audit-log.ts` 的 `sanitizeText()` 目前直接返回原文（规则留在注释里），
   若进入更严格环境需优先补齐
4. **无 i18n**：中文内联，面向多语言用户需要先抽文案
5. **定时任务依赖进程存活**：托盘常驻能缓解，但机器休眠/退出后不补跑
6. **设计文档与代码有漂移**：`doc/` 下部分设计稿记录的是当时的路径与方案，以代码为准

## 15. 一句话总结

**以 Electron 桌面壳为基座，以主进程为能力中枢，以模型为推理引擎，以系统工具 / Skills / Agents /
MCP / 能力模块为可执行能力层，以 React UI 承载会话与配置管理——Ergaster 是一个可控、可扩展、
可审计的本地桌面智能体工作间。**
