# 移除 Skill 全局启用开关 设计方案

> 状态：已评审，待实施
> 日期：2026-09-29
> 范围：Skills 管理面板全局开关、`enabled` 字段全链路移除、安装链路提示语调整

## 1. 背景与目标

### 背景

启用一个 skill 目前需要三步：安装 → 在 Skills 管理中打开全局开关 → 在智能体管理中勾选关联。经核实，**全局 `enabled` 开关在模型运行时工具管线中根本不生效**（`getUserTools` 只按 agent 的 `skillNames` 过滤，不看 `enabled`），它只影响两处：

1. 渲染层 `/` 指令候选菜单过滤（`use-chat-session.ts`）
2. Skills 管理 UI 的展示与编辑

这导致一个不一致：被"停用"的 skill 只要在某个 agent 的 `skillNames` 里，模型依然可以调用（只是 `/` 菜单不出现）。

### 目标

- 全局开关从 UI 与数据链路中**彻底移除**，`skillNames`（智能体管理勾选）成为 skill 生效的**唯一**入口，双轨变单轨。
- 模型自然语言安装 skill 后的引导文案与实际流程一致（不再引导去"Skills 面板启用"）。

### 已拍板决策

1. **彻底删除 `enabled` 字段**（shared 契约 / service / UI / 安装链路全量移除，不留恒真占位）。
2. **历史 skill 一律按"已就绪"对待**：SKILL.md 中残留的 `enabled: false` 键被解析后直接忽略，不迁移、不重写文件。
3. **安装后不自动授权任何智能体**（维持现状语义，`skillNames` 快照仍只在建 agent 时生成；自动授权默认智能体列为后续可选项，见 §8）。

## 5. 验证方案

1. **`npm run typecheck`** — 契约字段删除后所有引用点由编译器兜底（renderer 的 `skills.filter`、`SkillEditor` props、preload 类型等）
2. **`npm test`** — 现有测试全绿；`skill-source.test.ts` / `skill-scanner.test.ts` 不涉及 `enabled`，无需变更，也不新增测试文件（`user-skills-service` 顶层依赖 `app.getPath`，按既有架构约束不可直接测试）
3. **手动冒烟**（`npm run dev`）：
   - Skills 面板：列表与编辑表单均无开关；创建/编辑/删除正常
   - 安装一个 skill（本地 `SKILL.md` URL），确认：确认弹窗提示语新文案、安装成功回执新文案、SKILL.md 落盘不含 `enabled` 键
   - 智能体管理中勾选该 skill → 对话 `/` 菜单出现该 skill，模型工具列表中可见（`getRuntimeTools` 命中）
   - 构造一个含 `enabled: false` 的历史 SKILL.md → 重载后视为已就绪，智能体勾选后 `/` 菜单与工具均可用

## 6. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 无全局 kill switch | 停用 skill 需逐个 agent 取消勾选或删除 | 已确认接受（单 agent / 多数场景为 1 个常用 agent） |
| 历史 `enabled: false` 键残留 | 无（类型断言丢弃未知键，运行时不消费） | 决策 2；下次编辑该 skill 保存时 frontmatter 自动重写为无 `enabled` 键 |
| prompt 引导与功能脱节 | 模型要求用户做不可能的操作 | 本方案同步修订 3 处提示语，保持"引导至智能体管理勾选" |

回滚：纯删除性改动，`git revert` 即可；无数据迁移、无持久化格式变更（`agent.json` / `SKILL.md` 均不受影响）。
